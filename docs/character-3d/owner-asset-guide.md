# Owner guide: what art is needed and how to deliver it

Everything on screen today is a **TEMPORARY PLACEHOLDER**: low-poly shapes generated by `pnpm assets:generate`, with no third-party content and no licence obligations. Replace pieces one at a time; the game keeps working throughout.

## Delivery format (for the artist)

glTF 2.0 `.glb`, metres, Y up, facing +Z, feet at y = 0, canonical bone names (or a mapping), triangle and texture budgets from [performance.md](performance.md), meshopt-compressed if possible. Full rules: [character-import.md](character-import.md) and [equipment-attachments.md](equipment-attachments.md).

### Blender export hints

- Apply all transforms (Ctrl+A) and set the scene unit scale to 1.0 metres.
- Export Y-up; enable "Apply Modifiers"; disable cameras/lights.
- Limit vertex influences to 4, normalize weights, and keep the same armature (not a copy) for every garment.
- Keep morph targets as shape keys named exactly `build_lean`, `build_sturdy`, `face_wide`, `face_narrow`, `jaw_strong` on every skinned mesh.
- Export animations as separate actions named as in the clip table; bake mirrored `_L` clips.

## How to deliver one replacement

1. Save as `<name>_v2.glb` next to the placeholder (never overwrite `_v1`).
2. Update the manifest entry: `path`, `version: '2'`, `sizeBytes`, `checksumSha256`, `compression`.
3. `pnpm assets:validate`, then look at it in `/dressing-room` (dev **Debug** and attachment tuner).
4. Commit the GLB and the manifest change; delete `_v1` once nothing needs it.

Do not edit `character-assets.generated.ts` by hand once you stop using the generator: move real entries to a hand-maintained manifest module and keep `ASSET_MANIFEST` composed from it.

## Asking for help from code

If a model needs an offset other than the defaults, tune it live with the dev attachment tuner and paste the numbers into `character/visuals.ts`. If the skeleton differs, supply a `CharacterSkeletonMap` rather than renaming bones.
