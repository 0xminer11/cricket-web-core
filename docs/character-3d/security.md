# Security review (Module 5)

Scope: the character viewer, asset loading, inventory/equipment/appearance APIs and viewer telemetry. Authentication, sessions and CSRF are Module 3 and are reused unchanged.

| #   | Risk                                                                          | Control                                                                                                                                                                                                                                                                                                   | Evidence                                                 |
| --- | ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 1   | Client loads an arbitrary model URL (XSS, SSRF-like fetches, tracking pixels) | URLs exist only in the trusted manifest; the registry resolves **ids**; an id that is a URL is simply unknown. No API accepts a URL.                                                                                                                                                                      | unit test "CDN prefix … arbitrary URLs cannot be loaded" |
| 2   | Equipping an item you do not own / another player's item                      | Server resolves the inventory row by `(playerId, inventoryItemId)` (`getItem` raises an ownership violation otherwise); unknown and foreign ids both return `ITEM_NOT_OWNED` (404, no existence leak)                                                                                                     | API tests, E2E tampered request                          |
| 3   | Wrong slot, consumable, retired or over-level item                            | `INVALID_EQUIPMENT_SLOT`, `ITEM_SLOT_MISMATCH`, `ITEM_UNAVAILABLE`, `ITEM_REQUIREMENT_NOT_MET` enforced server-side; the UI check is only convenience                                                                                                                                                     | API tests                                                |
| 4   | Client-supplied stat modifiers or attributes                                  | Request bodies are strict schemas (`{ inventoryItemId }`, partial appearance); extra keys are rejected; modifiers come from game-core item definitions; equipment never writes attributes                                                                                                                 | API test "base attributes unchanged", E2E                |
| 5   | Unlocked/forged cosmetics                                                     | Appearance PATCH reuses creation validation: ids must exist, match category and be `starter` unlocks; height on the step grid                                                                                                                                                                             | API tests                                                |
| 6   | Equip races (double click, two tabs)                                          | One row per (player, slot); the repository replaces the occupant atomically, so concurrent equips leave exactly one item                                                                                                                                                                                  | concurrency test                                         |
| 7   | CSRF on the new PUT/PATCH routes                                              | Module 3 origin/CSRF checks apply; credentialed CORS lists `PUT`/`PATCH`; preflight tested                                                                                                                                                                                                                | API test                                                 |
| 8   | Abuse / flooding                                                              | Per-route rate limits (equip 60, appearance 30, telemetry 60 per window), all behind authentication                                                                                                                                                                                                       | route config                                             |
| 9   | Dev backdoor reaching production                                              | `/dev/player/grant-sample-gear` is **registered only when `APP_ENV` is development or test**; production returns 404 (tested). The UI button and `window.__viewer` exist only in non-production builds.                                                                                                   | API test                                                 |
| 10  | Telemetry as an injection or privacy channel                                  | Strict discriminated union; numeric bounds; failure reason is an enum; slot is `^[a-z_]{1,20}$`; only coarse counts and durations, never per frame; user id is attached server-side from the session; no free text                                                                                        | schema                                                   |
| 11  | Malicious GLB (parser exploits, huge files)                                   | Only files from our own origin/CDN listed in the manifest; SHA-256 and sizes are verified at build time; 20 s fetch timeout; cache bounded to 64 entries / 32 MB; decoders load only when the manifest asks. Treat uploads of user-made models as out of scope until a separate moderation design exists. | validator, loader                                        |
| 12  | Cache poisoning / stale assets                                                | Versioned file names with `immutable` caching in production; a changed asset is a new URL                                                                                                                                                                                                                 | header check                                             |
| 13  | Resource exhaustion in the browser                                            | on-demand render loop, pause when hidden/off-screen, ref-counted disposal, `forceContextLoss`, 20-cycle leak test                                                                                                                                                                                         | E2E                                                      |
| 14  | Third-party content / licences                                                | All art is generated by this repo (no third-party assets); three.js is MIT; see the source table in [owner-asset-guide.md](owner-asset-guide.md)                                                                                                                                                          | n/a                                                      |
| 15  | Information leaks in errors                                                   | Stable error codes with generic messages; ownership failures do not reveal whether an id exists                                                                                                                                                                                                           | API tests                                                |

## Review findings

- **Fixed during review**: the telemetry `slot` field was a free string; it is now restricted to lowercase letters and underscores.
- **Fixed during review**: the orbit camera swallowed clicks on overlay buttons (not a security issue, but it blocked the Retry control); see [fallbacks.md](fallbacks.md).
- **Accepted for now**: the dev sample-gear route has no rate limit (development/test only). Remove it with the shop module.
- **Out of scope**: user-uploaded models, marketplace trading of cosmetics, signed asset URLs. Revisit if any of these are introduced.

## Rules for future changes

1. Never add an endpoint or field that accepts a model URL, bone name, material value or modifier from the client.
2. Any new equipment rule is enforced in `EquipmentService`; the UI mirrors it, never replaces it.
3. New cosmetic options default to `locked` until the unlock path exists.
4. Keep development tools behind `APP_ENV` on the server **and** `NODE_ENV` in the client bundle.
