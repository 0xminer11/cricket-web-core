# Testing player creation

```bash
pnpm test                # unit tests (no Docker)
pnpm test:integration    # + PostgreSQL/Redis suites
pnpm test:e2e            # Playwright against the dev servers (needs a migrated dev database)
```

| Suite                                      | Covers                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tests/player/core.test.ts` (unit)         | starter config validation and failure detection; wallet/tier/level; loadout items and slots; every role/style combination (stats in range, comparable overall, specialist vs all-rounder shape, determinism); compatibility matrix; countries (249 ISO codes, no deprecated); jersey/hand/role errors; personality zero-sum trade-offs; appearance registry (unknown, wrong category, locked, height, asset ids); names (Indian and international scripts, normalisation, length in code points, invisible/control/bidi/emoji/markup); strict request schema (17 smuggled fields)                                                                                                      |
| `tests/player/creation.test.ts` (API + DB) | full guest creation with every table counted; registered and unauthenticated/suspended cases; one-per-user (app + DB); **concurrent creation** (same key and different keys); **idempotency** (replay, key reuse); wallet ledger exactness; kit exactness and ownership; **rollback with injected failure**; audit content; 24 invalid-choice cases; Unicode names; blocked terms (whole word); server-owned-state smuggling; CSRF/oversize; ownership isolation; every role × style persisted; options endpoint and exact previews = created stats; funnel events; **guest → create → upgrade keeps player, career, inventory, wallet**; logout/login; seeded players remain readable |
| `tests/db/player-creation.test.ts`         | migration 0004 columns and CHECKs; unique `user_id`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `tests/player/web.test.ts`                 | player client (cookies, header, null on missing), draft/step validation, no game rules/storage/fetch in components                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `e2e/player-creation.spec.ts`              | guest flow end to end (all five steps, review, welcome, `/career`, refresh, `/create-player` redirect, upgrade keeps the player); registered create → sign out → sign in; per-step validation and Back keeps choices; double click + two tabs → one cricketer; network failure keeps choices and retries with the same key; phone viewport (no horizontal scroll, ≥40px targets, labelled groups, heading focus)                                                                                                                                                                                                                                                                       |

Helpers: `tests/support/player.ts` (`createTestPlayerCreationRequest`, `authenticatedGuest`, `createPlayer`, `newIdempotencyKey`) over Module 3's `buildAuthApp` and `Browser`; Module 2's `createTestPlayer` now accepts `userId` to attach a player to an existing (guest) account.
